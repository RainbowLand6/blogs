# 什么是 Redis

Redis 是一个把数据主要放在内存中的键值数据库。因为读写内存很快，它经常用来做缓存，也能做计数器、排行榜、会话存储和消息队列。

## 1. 为什么需要缓存

假设商品详情每次都从数据库查询：

```text
用户请求 -> 应用服务 -> 数据库 -> 应用服务 -> 用户
```

热门商品被反复访问时，数据库会做大量重复工作。加上 Redis 后：

```text
用户请求 -> 应用服务 -> Redis 命中 -> 用户
                         └-> 未命中 -> 数据库 -> 写入 Redis
```

大部分请求不再访问数据库，响应更快，数据库压力也更小。

## 2. Redis 和数据库有什么区别

| 对比项 | Redis | MySQL 等关系型数据库 |
|---|---|---|
| 主要存储位置 | 内存 | 磁盘 |
| 擅长场景 | 高频读写、临时数据、简单结构 | 长期保存、复杂查询、事务关系 |
| 查询方式 | 按 Key 访问 | SQL 条件查询、关联查询 |
| 数据是否永久保存 | 可持久化，但通常不作为唯一数据源 | 通常作为核心数据源 |

一个实用原则：重要业务数据先写数据库，Redis 用于加速读取或保存可丢失的临时状态。不要只把订单、余额等核心数据放在 Redis。

## 3. 先认识三个概念

| 名词 | 含义 | 示例 |
|---|---|---|
| Key | 数据的名字 | `product:1001` |
| Value | Key 对应的数据 | 商品 JSON |
| TTL | 剩余存活时间 | 10 分钟 |

Redis 的 Key 建议用冒号分层命名：

```text
product:1001
user:42:profile
order:202607160001:status
```

这样看 Key 时能快速知道数据属于什么业务，也方便按前缀清理测试数据。

## 4. Redis 的常见用途

- **缓存**：商品详情、配置、字典数据。
- **计数器**：文章阅读数、接口访问次数。
- **排行榜**：游戏积分、热度排行。
- **会话**：登录状态、验证码。
- **分布式协调**：短时间互斥锁、限流。

## 5. Redis 不适合做什么

- 不适合替代关系型数据库保存所有核心业务数据。
- 不适合存非常大的文件或大对象。
- 不适合没有过期策略的无限缓存。
- 不适合把复杂查询逻辑硬塞进 Key 设计。
