# 过期时间与持久化

目标：知道哪些数据必须设置过期时间，以及 Redis 重启后数据为什么可能还在或消失。

## 1. 缓存必须考虑过期

缓存不是数据库的镜像备份。为缓存设置 TTL 可以：

- 防止旧数据长期存在。
- 控制内存占用。
- 让数据库更新后，缓存最终自动刷新。

常用命令：

```redis
SET product:1001 '{"id":1001,"name":"键盘"}' EX 600
TTL product:1001
EXPIRE product:1001 600
PERSIST product:1001
```

`PERSIST` 会移除过期时间。只有确认这个 Key 不需要自动清理时才使用它。

## 2. TTL 怎么选

没有放之四海而皆准的值，先按数据变化频率和允许旧数据的时长决定：

| 数据 | 常见起点 |
|---|---|
| 短信验证码 | 5 分钟 |
| 登录会话 | 30 分钟到数天，视安全策略而定 |
| 商品详情 | 5 到 30 分钟 |
| 字典、配置 | 数小时或主动删除 |

缓存时间不要全部设置成相同秒数。大量 Key 同时过期会造成缓存雪崩；第 7 篇会说明如何加入随机值。

## 3. Redis 持久化是什么

Redis 主要在内存中工作，但可以把数据保存到磁盘。常见方式：

| 方式 | 作用 |
|---|---|
| RDB | 定期生成某一时刻的数据快照，恢复快 |
| AOF | 记录写入操作，数据更完整，文件通常更大 |

本地 Compose 中的 `--appendonly yes` 就是开启 AOF。

## 4. 持久化不等于万无一失

即使开启持久化，仍可能因为宕机时机、磁盘故障或错误操作造成数据损失。核心业务数据仍应以数据库为准，并具备备份、恢复和监控方案。

## 5. 内存满了会怎样

Redis 内存有限。达到 `maxmemory` 后，Redis 会按照配置拒绝写入或淘汰旧 Key。缓存场景常使用 `allkeys-lru` 等淘汰策略，但不要把它用于不能丢失的关键数据。
