# 日志、资源与日常运维

目标：知道服务异常时看什么，并避免容器无限占用 CPU、内存和磁盘。

## 1. 查看日志

```bash
docker logs --tail 200 demo-app
docker logs -f demo-app
```

Docker 默认收集容器标准输出和标准错误。Java 应用应把主要日志输出到控制台，再由 Docker 或日志平台统一采集；不要只写进容器内部文件。

## 2. 查看资源

```bash
docker stats
docker system df
```

`docker stats` 用于观察 CPU、内存、网络和磁盘 I/O。`docker system df` 用于查看镜像、容器、卷占用了多少磁盘。

## 3. 限制容器资源

```bash
docker run -d \
  --name demo-app \
  --memory 1g \
  --cpus 1.5 \
  -p 8080:8080 \
  demo-app:1.0.0
```

资源限制要与 JVM 参数协同。给容器 1GB 内存时，Java 堆不能配置为 1GB；还要为元空间、线程栈、直接内存和系统开销留余量。

## 4. 健康检查

镜像可以定义健康检查：

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=60s --retries=3 \
  CMD wget -qO- http://127.0.0.1:8080/actuator/health || exit 1
```

这要求镜像内存在 `wget`，且 Spring Boot 开启了 Actuator 健康端点。健康检查状态可通过 `docker ps` 查看。

## 5. 清理不要鲁莽

查看：

```bash
docker image ls
docker container ls -a
docker volume ls
```

`docker system prune` 会删除未使用资源。生产服务器执行前先用 `docker system df` 评估，尤其不要随意加 `--volumes`，以免误删仍需保留的数据卷。
