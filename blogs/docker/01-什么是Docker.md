# 什么是 Docker

Docker 是一个把应用和运行环境一起打包、一起运行的工具。它解决的是“我电脑上能跑，服务器上却跑不起来”的一类问题。

## 1. 传统部署的问题

部署一个 Java 服务，通常要处理：

- 服务器是否安装了正确的 JDK。
- 依赖的系统库版本是否匹配。
- 同一台服务器上多个项目会不会互相影响。
- 新机器如何快速复制相同环境。

Docker 把应用和依赖封装到镜像中。服务器只需要安装 Docker，就能按相同方式运行。

```text
代码 + JDK + 启动命令 -> Docker 镜像 -> Docker 容器
```

## 2. 三个最重要的词

| 名词 | 含义 | 类比 |
|---|---|---|
| Image（镜像） | 只读的运行模板 | 安装包、类 |
| Container（容器） | 镜像启动后的一次运行实例 | 已运行的程序、对象 |
| Registry（镜像仓库） | 存放和分发镜像的地方 | Maven 仓库 |

同一个镜像可以运行多个容器：

```text
nginx:alpine 镜像
├── web-1 容器
└── web-2 容器
```

## 3. Docker 和虚拟机的区别

虚拟机通常包含完整操作系统；容器共享宿主机 Linux 内核，只隔离进程、网络和文件系统。因此容器启动更快、资源开销更小。

Docker 不是虚拟机，也不是安全边界的万能替代品。容器仍需要限制权限、控制网络和使用可信镜像。

## 4. Docker 适合什么

- 快速搭建开发和测试环境。
- 部署 Java、Node.js、Python、Nginx 等服务。
- 让多个服务在同一份 Compose 配置中启动。
- 构建可重复的 CI/CD 发布流程。

## 5. Docker 不自动解决什么

- 容器内的数据持久化与备份。
- 应用本身的数据库事务和业务正确性。
- 多台机器的高可用、服务发现和自动扩缩容。
- 镜像中的安全漏洞。
