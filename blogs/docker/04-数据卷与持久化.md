# 数据卷与持久化

目标：理解容器文件系统为什么会丢数据，并能用 Volume 保存 MySQL、Redis 等服务数据。

## 1. 容器删除后，内部文件会怎样

容器自身可写层会随着容器删除而删除：

```text
容器内 /var/lib/mysql 的数据
  -> 未挂载 Volume
  -> docker rm 后丢失
```

因此数据库、上传文件、日志等需要长期保留的数据，必须写到 Volume 或宿主机目录。

## 2. 使用命名 Volume

创建 Volume：

```bash
docker volume create mysql-data
docker volume ls
```

运行 MySQL：

```bash
docker run -d \
  --name mysql-demo \
  -e MYSQL_ROOT_PASSWORD=change-me \
  -e MYSQL_DATABASE=demo \
  -v mysql-data:/var/lib/mysql \
  mysql:8.4
```

`mysql-data:/var/lib/mysql` 表示把容器中的数据目录挂载到 Docker 管理的命名卷。

## 3. 使用宿主机目录挂载

配置文件、静态文件常需要直接编辑，可挂载宿主机目录：

```bash
mkdir -p ~/docker-demo/html
echo "Hello Docker" > ~/docker-demo/html/index.html

docker run -d \
  --name nginx-html \
  -p 8081:80 \
  -v ~/docker-demo/html:/usr/share/nginx/html:ro \
  nginx:alpine
```

末尾的 `:ro` 表示只读挂载。容器不需要写入时优先使用只读，降低误写风险。

## 4. Volume 的常用操作

```bash
docker volume inspect mysql-data
docker volume ls
docker volume rm mysql-data
```

`docker volume rm` 会永久删除卷数据。删除前必须确认没有业务容器使用它，并已完成备份。

## 5. 数据备份思路

Volume 不是备份。可靠备份至少包括：

- MySQL 等数据库使用自身的逻辑备份或物理备份工具。
- 定期把备份文件同步到另一台机器或对象存储。
- 定期做恢复演练，确认备份真的可用。
