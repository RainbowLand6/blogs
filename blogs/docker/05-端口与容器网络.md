# 端口与容器网络

目标：分清“容器端口”“主机端口”和“容器服务名”，避免把数据库错误暴露到公网。

## 1. `-p` 的含义

```bash
docker run -p 8080:80 nginx:alpine
```

格式是：

```text
主机端口:容器端口
```

访问 Linux 服务器的 `8080`，请求会被转发到容器里的 `80`。

如果服务只给本机 Nginx 或同机程序使用，绑定到回环地址：

```bash
docker run -p 127.0.0.1:3306:3306 mysql:8.4
```

这样外部网络不能直接访问 MySQL 端口。

## 2. 自定义网络

创建一个网络：

```bash
docker network create app-net
```

将 MySQL 和应用容器接入同一网络：

```bash
docker run -d --name mysql --network app-net \
  -e MYSQL_ROOT_PASSWORD=change-me \
  mysql:8.4

docker run --rm --network app-net \
  alpine:3.20 \
  ping -c 1 mysql
```

同一自定义网络中的容器可以通过容器名互相访问。应用连接 MySQL 时，应使用：

```text
jdbc:mysql://mysql:3306/demo
```

而不是 `localhost:3306`。在容器内部，`localhost` 指向容器自己。

## 3. 查看网络

```bash
docker network ls
docker network inspect app-net
```

## 4. 网络安全原则

- 数据库、Redis、Elasticsearch 通常不需要映射到公网。
- 只暴露真正对外服务的端口，例如 Nginx 的 80/443。
- 容器间通过自定义网络通信，不要用宿主机公网 IP 绕一圈。
- 云服务器安全组和 Linux 防火墙也应只放行必要端口。
