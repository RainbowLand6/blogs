# 12-安全、备份、监控与故障排查

Jenkins 一旦能部署代码，就已经是重要系统。最后一章把日常最关键的维护动作集中起来。

## 安全基线

- 不要把 Jenkins 直接裸露在公网。
- 启用登录认证；团队环境按角色分配权限，不共享管理员账号。
- 凭据保存在 Credentials，不提交到仓库，不打印到日志。
- Controller 尽量只负责调度，构建在隔离 Agent 中执行。
- 定期升级 Jenkins LTS 和已安装插件，升级前先备份。
- 审核谁能修改 `Jenkinsfile`。能修改流水线的人，通常也能影响部署动作。

## 备份什么

Docker 安装时，核心数据在 `/var/jenkins_home`，也就是本教程的 `jenkins_home` 数据卷。

备份前先停止 Jenkins，避免复制过程中数据变化：

```bash
docker stop jenkins
docker run --rm \
  -v jenkins_home:/source:ro \
  -v "$(pwd)":/backup \
  alpine tar czf /backup/jenkins-home-backup.tgz -C /source .
docker start jenkins
```

恢复时应在测试环境先验证备份可用，再覆盖生产数据。备份文件本身可能含有加密凭据和配置，必须按敏感数据保护。

## 监控什么

最实用的四项：

| 指标 | 风险 |
| --- | --- |
| Controller CPU、内存、磁盘 | 磁盘满会导致构建、插件和配置异常。 |
| 构建队列长度 | Agent 数量不足，或某类任务长期阻塞。 |
| Agent 在线状态 | 节点断开后任务无法执行。 |
| 失败率和构建耗时 | 依赖、网络或代码质量出现变化。 |

## 常见故障排查顺序

### 构建失败

1. 打开失败构建的 Console Output。
2. 找到第一个真正的 `ERROR` 或非零退出码，而不是只看最后一行。
3. 判断是代码、依赖、凭据、网络还是执行节点问题。
4. 在同一 Agent 上复现必要命令。

### Workspace 异常

症状包括旧文件影响构建、磁盘增长、Git 状态混乱。可在构建前或构建后使用：

```groovy
cleanWs()
```

但不要依赖清理来掩盖构建脚本的路径错误。

### Jenkins 页面无法访问

Docker 环境先看：

```bash
docker ps -a --filter name=jenkins
docker logs --tail 200 jenkins
docker volume inspect jenkins_home
```

优先确认容器状态、端口占用、磁盘空间和日志中的第一条异常。

## 最终完成标志

你已经有一条从 Git 拉代码、测试、打包、保存制品到部署测试环境的流水线；同时知道凭据放哪里、数据备份在哪里，以及失败时先看什么。

接下来最值得做的是：选一个真实但低风险的项目，把教程中的 `Jenkinsfile` 改成该项目的构建命令，然后逐步接入测试环境。
