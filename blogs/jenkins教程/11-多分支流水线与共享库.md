# 11-多分支流水线与共享库

## 多分支流水线解决什么问题

普通 Pipeline 任务通常固定构建一个分支。多分支流水线（Multibranch Pipeline）会扫描仓库中的分支和 Pull Request，只要它们带有 `Jenkinsfile`，就自动创建对应任务。

适合：

- `main`、`develop`、功能分支有不同构建需求。
- 希望 Pull Request 自动跑测试。
- 不想为每个新分支手工创建 Jenkins 任务。

## 创建多分支流水线

1. 点击 **New Item**。
2. 选择 **Multibranch Pipeline**。
3. 在 Branch Sources 添加 GitHub、GitLab 或 Git 源。
4. 配置仓库地址与凭据。
5. 保存并点击 **Scan Multibranch Pipeline Now**。

扫描后，带有 `Jenkinsfile` 的分支会显示在任务内。

## 分支差异写法

可以根据分支控制部署阶段：

```groovy
stage('部署测试环境') {
    when {
        branch 'develop'
    }
    steps {
        sh './deploy-test.sh'
    }
}

stage('生产确认') {
    when {
        branch 'main'
    }
    steps {
        input message: '确认发布生产环境？', ok: '发布'
    }
}
```

建议让功能分支只执行检查和测试；测试环境部署由 `develop` 执行；生产发布只允许受保护的 `main` 分支触发。

## 什么是共享库

当多个项目都有重复流水线步骤，例如“构建 Java 项目”“推送镜像”“发通知”，可以将其抽到 Shared Library，避免每个仓库复制一大段 `Jenkinsfile`。

典型目录：

```text
jenkins-shared-library/
├── vars/
│   └── javaBuild.groovy
└── src/
    └── org/example/Notify.groovy
```

`vars/javaBuild.groovy`：

```groovy
def call() {
    sh 'mvn -B test'
    sh 'mvn -B package -DskipTests'
}
```

项目中的 `Jenkinsfile`：

```groovy
@Library('company-ci') _

pipeline {
    agent any
    stages {
        stage('构建') {
            steps {
                javaBuild()
            }
        }
    }
}
```

## 共享库的边界

共享库应只沉淀稳定、重复、跨项目通用的逻辑。业务项目特有的部署细节仍应留在项目仓库中，否则排错会变得困难。

## 本章完成标志

你能说明多分支流水线如何发现分支，并知道共享库的目的不是“把所有 Jenkinsfile 都藏起来”，而是复用稳定的公共步骤。
