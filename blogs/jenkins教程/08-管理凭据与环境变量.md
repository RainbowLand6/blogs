# 08-管理凭据与环境变量

## 绝对不要这样做

不要把密码、Token、私钥直接写在 `Jenkinsfile`：

```groovy
// 错误示例：不要提交这种内容
sh 'docker login -u my-user -p my-secret-password'
```

代码库会保存历史记录，泄露后的 Token 即使删除代码也可能仍可被找回。

## 在 Jenkins 中创建凭据

进入 **Manage Jenkins -> Credentials -> System -> Global credentials -> Add Credentials**。

常见类型：

| 类型 | 适用场景 |
| --- | --- |
| Username with password | 镜像仓库账号密码、部分 Git 服务。 |
| Secret text | API Token、Webhook Token。 |
| SSH Username with private key | 使用 SSH 拉取 Git 仓库、登录服务器。 |
| Secret file | 配置文件、云服务密钥文件。 |

为凭据设置稳定且有含义的 ID，例如 `gitlab-read-token`、`docker-registry-prod`。不要用用途不明的 `token1`。

## 在流水线中使用 Secret text

假设已创建 ID 为 `demo-api-token` 的 Secret text：

```groovy
pipeline {
    agent any

    stages {
        stage('调用接口') {
            steps {
                withCredentials([string(credentialsId: 'demo-api-token', variable: 'API_TOKEN')]) {
                    sh '''
                        curl -H "Authorization: Bearer $API_TOKEN" \
                          https://example.invalid/api/health
                    '''
                }
            }
        }
    }
}
```

`withCredentials` 的作用范围仅限于代码块内部。Jenkins 会尝试在控制台日志中掩码凭据，但这不是让你随意打印密钥的理由。

## 在流水线中使用账号密码

```groovy
withCredentials([usernamePassword(
    credentialsId: 'docker-registry-test',
    usernameVariable: 'REGISTRY_USER',
    passwordVariable: 'REGISTRY_PASSWORD'
)]) {
    sh '''
        echo "$REGISTRY_PASSWORD" | docker login registry.example.com \
          --username "$REGISTRY_USER" --password-stdin
    '''
}
```

使用 `--password-stdin`，不要把密码作为命令行参数传入。

## 环境变量和凭据的区别

普通环境变量可写在 `environment`：

```groovy
environment {
    APP_NAME = 'demo-service'
    DEPLOY_ENV = 'test'
}
```

它们适合存放公开配置，不适合存放密码。密码、Token、私钥必须使用 Credentials。

## 本章完成标志

你能创建一种 Jenkins 凭据，并能说明为什么敏感信息不能放进 Git 仓库或普通环境变量。
