# 分页、排序与高亮

目标：让搜索接口能返回指定页、按价格排序，并在结果中标记命中的关键词。

## 1. 基础分页

```json
GET /products/_search
{
  "from": 0,
  "size": 10,
  "query": {
    "match": {
      "name": "蓝牙"
    }
  }
}
```

页码从 1 开始时：

```text
from = (pageNo - 1) * pageSize
```

例如第 3 页、每页 10 条，`from` 是 20。

## 2. 排序

```json
GET /products/_search
{
  "query": {
    "match_all": {}
  },
  "sort": [
    {
      "price": {
        "order": "asc"
      }
    }
  ]
}
```

排序字段应是 `keyword`、数值、日期等适合排序的类型。全文检索时通常先按 `_score`，再按销量或时间做次级排序。

## 3. 高亮

```json
GET /products/_search
{
  "query": {
    "match": {
      "name": "蓝牙"
    }
  },
  "highlight": {
    "fields": {
      "name": {}
    }
  }
}
```

响应中的 `highlight.name` 会包含带标签的命中文字片段。前端展示时应做安全转义，只允许预期的高亮标签。

## 4. 深分页为什么有问题

`from + size` 很大时，Elasticsearch 需要让各分片准备并丢弃大量前面的结果，成本会快速增加。

后台管理的浅分页可以使用 `from + size`。连续导出或无限滚动应使用 `search_after`、Point in Time（PIT）等方式，而不是把页码无限增大。

## 5. Java 中的分页搜索

```java
var response = client.search(request -> request
        .index("products")
        .from(0)
        .size(10)
        .query(query -> query.match(match -> match
                .field("name")
                .query("蓝牙"))),
        Product.class);
```
