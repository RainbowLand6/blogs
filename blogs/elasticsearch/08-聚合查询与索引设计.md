# 聚合查询与索引设计

目标：按品牌统计商品数量，并掌握几个避免后期返工的 Mapping 原则。

## 1. 什么是聚合

聚合不是返回每一条商品，而是返回统计结果。例如“每个品牌有多少商品”：

```json
GET /products/_search
{
  "size": 0,
  "aggs": {
    "brand_count": {
      "terms": {
        "field": "brand"
      }
    }
  }
}
```

`size: 0` 表示不需要普通搜索结果，只需要统计。

## 2. 价格统计

```json
GET /products/_search
{
  "size": 0,
  "aggs": {
    "price_stats": {
      "stats": {
        "field": "price"
      }
    }
  }
}
```

结果会包括 `min`、`max`、`avg`、`sum`、`count`。

## 3. 聚合字段的要求

聚合通常使用 `keyword`、数值或日期字段：

```text
品牌筛选/统计：brand（keyword）
按商品名完整值统计：name.keyword
价格统计：price（double）
```

不要对普通 `text` 字段直接做 `terms` 聚合。它为全文搜索设计，字段值会被拆词，内存成本也更高。

## 4. Mapping 设计四条原则

1. 搜索文本用 `text`，筛选、排序、聚合用 `keyword` 或数值类型。
2. 预先确定重要字段类型，避免动态映射把数字写成文本。
3. 文档不要无限膨胀。大数组、超长正文、嵌套对象都会影响索引和查询成本。
4. 字段数量要克制。用户传入任意 JSON 并自动建字段，容易造成 Mapping 爆炸。

## 5. 中文搜索要单独评估

默认分析器未必符合中文商品搜索的预期。中文分词通常需要合适的分析器、同义词和搜索测试集。先用真实搜索词评估召回和排序，再决定是否引入专用插件或词库，不要只因为“支持中文”就直接上线。
