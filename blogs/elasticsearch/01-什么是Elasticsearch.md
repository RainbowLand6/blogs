# 什么是 Elasticsearch

Elasticsearch 是一个分布式搜索和分析引擎。它擅长从大量文本或结构化数据中快速找出匹配结果，也能做筛选、排序、聚合统计。

## 1. 为什么数据库查询还不够

数据库很擅长按主键查订单、做事务、维护业务数据。但当需求变成：

```text
搜索“无线蓝牙耳机”
按价格区间筛选
按销量排序
统计每个品牌的商品数量
```

就需要频繁使用模糊匹配、组合筛选和统计。把所有这类压力都交给关系型数据库，查询会越来越复杂且成本高。

Elasticsearch 会为字段建立倒排索引，让“哪些文档包含某个词”可以快速定位。

```text
文档 1：无线 蓝牙 耳机
文档 2：蓝牙 键盘

倒排索引：
蓝牙 -> 文档 1、文档 2
耳机 -> 文档 1
```

## 2. Elasticsearch 和数据库的关系

Elasticsearch 通常不是订单、余额等核心数据的唯一来源。更常见的架构是：

```text
MySQL（业务真相） -> 同步程序/消息队列 -> Elasticsearch（搜索副本）
```

用户搜索时查 Elasticsearch；创建订单、扣库存等核心业务仍以数据库事务为准。

## 3. 六个基础名词

| 名词 | 小白解释 | 类比 |
|---|---|---|
| Cluster | 多台 Elasticsearch 节点组成的整体 | 数据库集群 |
| Node | 集群中的一台服务 | 一台数据库服务器 |
| Index | 一类文档的集合 | 一张表 |
| Document | 一条 JSON 数据 | 一行记录 |
| Field | 文档中的属性 | 一列 |
| Mapping | 字段类型和索引规则 | 表结构的一部分 |

例如：

```json
{
  "id": 1001,
  "name": "无线蓝牙耳机",
  "brand": "SoundGo",
  "price": 299.0
}
```

可以存入 `products` 索引，整条 JSON 就是一份文档。

## 4. Elasticsearch 适合什么

- 商品、文章、日志等全文搜索。
- 多条件筛选和排序。
- 数据聚合，例如按品牌、日期、地区统计。
- 日志检索与分析。

## 5. Elasticsearch 不适合什么

- 不替代关系型数据库的事务能力。
- 不适合频繁按单条记录进行复杂事务更新。
- 不适合没有设计 Mapping 就无限写入任意 JSON。
- 不适合把数据库的多表关联查询原样搬过去。
